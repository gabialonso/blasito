# Publishing Blasito to Firefox Add-ons

This file is the maintainer checklist for submitting a new version to
[addons.mozilla.org (AMO)](https://addons.mozilla.org/developers/). It holds what to upload,
the notes for the reviewer and the answers for the listing. It is not user documentation
(see [README.md](../README.md)). AMO rules change; check each field against the form when you submit.

## 1. Build the packages

```bash
npm ci
npm run typecheck && npm test
npm run package        # blasito-chrome.zip, blasito-firefox.zip and blasito-source.zip
npm run lint:firefox   # Mozilla's validator; it must report 0 errors
```

Commit everything before packaging: `blasito-source.zip` comes from `git archive HEAD`, so
uncommitted changes are left out of it.

The Firefox manifest is generated by `scripts/build-firefox.mjs` from the Chrome one. It sets:

- the add-on ID `blasito@usuallygabo`, which must never change;
- Firefox 140 or newer, the first version that shows the data collection declaration at install;
- `data_collection_permissions: none`;
- `options_ui` instead of `options_page`.

## 2. Upload

1. **Where:** on AMO, choose **On this site** so the add-on is listed and signed by Mozilla.
2. **Package:** upload `blasito-firefox.zip`. The automatic validation must pass with no errors.
3. **Platforms:** Firefox for desktop only. Leave Firefox for Android unchecked until it has been tested there.
4. **Source code:** answer **Yes** and upload `blasito-source.zip`. Vite bundles and minifies the code, so reviewers need the source to rebuild it.
5. **Notes to reviewer:** paste this text.

```text
Blasito is written in TypeScript and bundled with Vite. To rebuild the uploaded package from blasito-source.zip:

Requirements: Node.js 22.12 or newer and npm, on Linux or macOS (the build uses cp).

  npm ci
  npm run build

The add-on is the dist-firefox/ folder; it matches blasito-firefox.zip.
dist-firefox/ is the Chrome build (dist/) with a manifest adapted by scripts/build-firefox.mjs.

The extension makes no network requests and has no remote code. The extension pages
carry a CSP with connect-src 'none'. The content script only reads the text before the
cursor, and only when the typed character could finish one of the user's saved shortcuts.
Password and other non-text fields are ignored, and synthetic (untrusted) input events are dropped.

To try it: open the options page, create a snippet with shortcut /hi, then type /hi in any text field.
```

## 3. Listing

**Name:** Blasito

**Summary:** the same text as the Chrome Web Store, from `extensionDescription` in
`public/_locales/<language>/messages.json` (max 132 characters for Chrome; AMO accepts up to 250).

**Description:** reuse the English and Spanish descriptions in
[chrome-web-store.md](chrome-web-store.md#2-store-listing). Add Spanish as a localized listing.

**Category:** choose the closest one in the form (productivity or other, depending on the current list).

**Images:** the screenshots in `store/en/` and `store/es/` (1280×800). AMO does not use the promo tile.

**Links:**

- Homepage / support: https://github.com/usuallygabo/blasito
- Privacy policy: paste the text of [PRIVACY.md](../PRIVACY.md) into the privacy policy field.
- License: MIT.

## 4. Permissions and data

- **Data collection:** none. It is declared in the manifest and shown at install.
- **`storage`:** saves the user's snippets locally.
- **Access to all websites** (content script on `<all_urls>`, all frames): the user can type a shortcut in any text field on any site, including editors inside iframes. Firefox grants it at install, and the user can revoke it in `about:addons`. Without it, nothing expands but nothing breaks.

## 5. Before submitting

- [ ] Version bumped in `public/manifest.json`, `package.json` and `package-lock.json`. AMO rejects a version it has already seen.
- [ ] `npm run typecheck && npm test && npm run package && npm run lint:firefox` pass, with no uncommitted changes.
- [ ] `dist-firefox/` loaded in Firefox from `about:debugging` → **This Firefox** → **Load Temporary Add-on** → `dist-firefox/manifest.json`, and tried by hand:
  - [ ] create a snippet and expand it in a textarea and in a rich editor;
  - [ ] copy from the popup;
  - [ ] import and export;
  - [ ] switch between ES and EN;
  - [ ] check the popup and options page consoles show no CSP errors.
- [ ] Upload `blasito-firefox.zip` and `blasito-source.zip`, fill in the listing and submit for review.
